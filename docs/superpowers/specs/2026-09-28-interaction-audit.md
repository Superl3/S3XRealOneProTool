# 핸드 마우스 상호작용 전수 검토 (2026-09-28)

코드 읽기로만 검토했고, 실기기 검증은 하지 않았다. 코드 변경도 없다. 기준은 같은 날의 시간 기준·주먹 클릭 변경(`2026-09-28-hand-tracking-fundamentals.md`)을 적용한 뒤의 코드다.

## 결론: 핀치 삭제 비추천

핀치에만 걸려 있는 역할이 4개다. 주먹으로 옮길 수 있는 것은 탭뿐이다.

| 역할 | 지금 구현 | 주먹으로 대체 |
|---|---|---|
| 탭 | 핀치 DOWN 확정 → 뗄 때 탭. 위치는 DOWN 확정 120ms 전 | 이미 있음 |
| 더블탭 | 앱은 탭 2번만 보냄. 판정은 안드로이드가 함(`GestureInjector.doubleTap` 호출 없음) | 불가. 주먹 한 번에 확정 대기 225ms + 다시 쥐는 시간이 걸려, 탭 간격이 안드로이드 더블탭 제한 300ms를 넘음(추정) |
| 드래그·스크롤 | 400ms 이상 유지 + 28px 이상 이동 | '주먹 = 마우스 버튼'(펼 때 클릭)이 필요. 지난번에 고르지 않은 방식 |
| 메뉴 열기 | 움직이지 않고 900ms 유지 | 새 트리거 필요 |
| 메뉴 확정 | 메뉴에서 핀치 DOWN | 충돌. 메뉴에서 주먹은 '취소' |

대안:
- **A. 핀치의 탭 역할만 끄는 설정.** 먼저 할 것으로 추천. 핀치 오클릭 경로와 C2가 없어진다. 대신 '핀치 두 번 = 더블탭'이 사라진다. 기본값은 사용자가 결정.
- **B. 핀치 = 손가락 터치.** 핀치 DOWN 순간 주입 터치를 누르고, 이동하면 따라가고, 뗄 때 뗀다. 롱프레스와 길게 눌러 끌기가 생기지만 메뉴 트리거를 옮겨야 한다. DeX 보조 디스플레이가 continueStroke를 취소한 기록(2026-07-22)이 있어 실기기 검증이 필수다.
- **C. 핀치 완전 삭제 + 주먹 = 버튼.** 비추천. 클릭이 펼 때로 늦어지고, 더블탭이 불가능하고, 메뉴를 새로 설계해야 한다.

## 결함

- **C1.** 메뉴를 연 뒤 핀치를 떼면 phase가 IDLE이 되어 엄지척(`CursorPipeline.kt:386`)·V(`:541`) 판정이 통과한다. 이때 음소거나 음성 듣기로 들어가면 `layeredMenu`가 리셋되지 않는다. `setHiddenByUser`는 커서 뷰만 숨기므로, 멈춘 메뉴가 화면에 남는다.
- **C2.** 핀치를 막는 `fistSuppressesPinch`(`:333`)는 주먹이 확정된 뒤에만 참이다. 주먹을 쥐는 도중 핀치 DOWN이 먼저 확정되고 링이 닫히기 전에 손을 펴면, 핀치 UP으로 Click이 나간다. 링의 '펴면 취소' 약속이 깨지는 경로다. 실기기에서 얼마나 자주 생기는지는 모른다.
- **C3.** 주먹을 먼저 쥔 뒤 엄지를 세우는 습관이면, 엄지척(음소거)보다 주먹 클릭이 먼저 나간다(습관 의존).
- **C4.** '짧은 핀치 두 번 — 더블탭'은 안드로이드 판정에 맡긴 것이다. 두 번째 탭이 두 번째 핀치를 뗄 때 나가므로 간격이 300ms 경계에 걸린다(추정).
- **C5.** 롱프레스를 할 방법이 없다. 정지 핀치는 400–900ms면 클릭, 900ms 이상이면 메뉴가 된다.
- **C6.** 음성 '닫기/close'는 홈으로 간다(`VoiceCommand.kt:40,46`). 그런데 메뉴의 '창 닫기'는 `WindowController.closeApp`으로 실제 창을 닫는다.
- **문서.** `EYE_TOOLS_KO.md:19`는 메뉴를 '손바닥 펴기'로 연다고 적었지만, 코드와 앱 문구는 '제자리 롱 핀치'다. '중앙으로 돌아오면 취소'도 실제로는 선택 해제만 되고 메뉴는 열려 있다.
- **죽은 코드.** `PalmSwipeDetector`(+테스트), `GestureInjector.doubleTap`, `LayeredMenuTracker.onPalmClosed`/`confirmWindowMs`, `setInjectionSuppressed` 경로(보정 마법사가 없어진 뒤 호출하는 곳 없음).

## 확장 여지

1. 주먹 링이 시작될 때 자석 스냅 착지점을 미리 표시(`AccessibleTargetFinder.nearest`는 링 시작 때 한 번만 호출).
2. 유예 중이거나 손을 놓쳤을 때 커서를 회색으로 표시.
3. 음성 '닫기'를 `WindowController`로 연결.
4. 롱프레스·길게 눌러 끌기(대안 B, 또는 메뉴 항목).
5. 스크롤 전용 제스처(`PalmSwipeDetector`를 되살리거나 삭제).

## 적용 결과 (같은 날 후속 작업)

검증: `testDebugUnitTest` 222개 통과(건너뜀 2 = 녹화 파일이 없을 때 건너뛰는 E2E), `assembleDebug` 성공. **실기기 확인 안 함.** `CursorPipeline`은 Android 클래스에 묶여 있어 C1·C2·힌트는 JVM 테스트로 검증하지 못했다.

| 항목 | 변경 |
|---|---|
| C1 | 메뉴가 열린 동안 엄지척·V hold를 막음. 음소거·음성 듣기로 들어갈 때 메뉴를 닫음(`closeMenuIfOpen`) |
| C2 | 주먹 확정을 기다리는 동안(`enterProgress > 0`) 핀치 DOWN을 보류. 주먹을 포기하거나 대기 중에 핀치를 떼면 PRESSED를 버림 |
| C6 | `VoiceCommand.CloseApp` 추가. '닫기'·'창 닫기'·'close'를 `WindowController.closeApp`(커서 위치)으로 연결 |
| E1 | 주먹 링이 시작될 때 클릭 계획을 한 번 세움(굽히기 직전 위치 → 자석 스냅). 착지점을 `ClickMarkerView.holdAt`으로 미리 표시하고, 확정되면 그 좌표를 그대로 탭. 속도 검사에 걸려 버려지는 주먹은 링도 띄우지 않음 |
| 제스처 안내 | `GestureHint` + 커서 아래 한 줄(`CursorOverlay.setHint`). 설정 "제스처 안내" 기본 켬. 핀치 안내는 200ms 이상 유지할 때부터 표시(빠른 탭에서 글자가 깜빡이지 않게). 대기·음소거 중에는 표시 안 함(사용자가 고른 형태) |
| 문서 | EYE_TOOLS_KO: 메뉴 행을 '롱 핀치 메뉴'로 수정, DeX 무간섭 설명, 주먹 행, 제스처 안내 행, 음성 명령 목록 |

**하지 않은 것과 이유**
- 대안 A(핀치 탭 끄기): 다음 작업 선택에서 고르지 않음.
- 대안 B(핀치 = 터치): 고르지 않음. 실험 브랜치와 실기기 확인이 필요.
- C3(주먹→엄지척 순서), C5(롱프레스): 선택 범위 밖.
- C4: 앱 안내 문구 `gestures_list`의 '짧은 핀치 두 번 — 더블탭'을 그대로 둠(선택 범위 밖).
- 죽은 코드 정리: 지울지 되살릴지 결정되지 않음.
